## 1. Security

### 1.1 Authentication & Authorization
- [x] **1.1.1** `ResolveApiKeyAsync()` calls AWS Secrets Manager on **every request** with no caching — this is a network call per RPC. Cache the resolved key with a short TTL (e.g., 5 minutes via `IMemoryCache`). ✅ *Fixed — `IMemoryCache` injected into handler; resolved key cached with 5-minute TTL.*
- [x] **1.1.2** The constant-time comparison in `IsApiKeyMatch` short-circuits on length mismatch before calling `FixedTimeEquals`. For fixed-length API keys this is acceptable, but document this assumption explicitly or pad to fixed length. ✅ *Fixed — documented inline with guidance on variable-length keys.*
- [x] **1.1.3** All authenticated claims are hard-coded to static string literals — every API key holder gets the same identity. Add per-client identity (client ID claim) to support per-client audit trails and fine-grained authorization. ✅ *Fixed — `ComputeClientId()` derives a stable SHA-256-based client ID from the API key.*
- [x] **1.1.4** The fallback authorization policy requires authentication but has no role or scope claims check. Define at least one named policy so RPC methods can be decorated with `[Authorize(Policy = "...")]`. ✅ *Fixed — `"ForgeServiceConsumer"` named policy added alongside the fallback policy.*
- [ ] **1.1.5** mTLS is listed as the preferred east-west identity mechanism but no setup guidance, certificate loading code, or Kestrel TLS configuration exists in the scaffold. Add at minimum a commented Kestrel config block and a placeholder for cert resolution.

### 1.2 Middleware & Pipeline Order (Critical Bug)
- [x] **1.2.1** **CRITICAL** — The audit logging middleware runs **before** `app.UseAuthentication()`. `context.User.Identity?.IsAuthenticated` is always `false` at that point, so every audit log entry records `"anonymous"` as the actor, even for authenticated requests. Move `app.UseAuthentication()` and `app.UseAuthorization()` **before** both custom middleware blocks. ✅ *Fixed — `UseAuthentication()`, `UseRateLimiter()`, `UseAuthorization()` now run before audit/security middleware.*

### 1.3 Input Validation
- [ ] **1.3.1** There is no request validation interceptor or middleware. Proto fields arrive as their zero-values (empty string, 0) if not set — callers can send blank fields with no rejection. The scaffold should include a `ValidationInterceptor` stub or guidance for using a validation library (e.g., `FluentValidation`) at the service layer.
- [x] **1.3.2** The generated `ServiceImpl` catches all exceptions (`catch` with no type filter) including `OperationCanceledException`. Cancellation should not be treated as an error for metrics/telemetry purposes. The scaffold example should add an explicit `catch (OperationCanceledException)` that re-throws without incrementing error counters. ✅ *Fixed — explicit `catch (OperationCanceledException)` added with `result = "cancelled"` and re-throw.*

### 1.4 HTTP Security Headers
- [ ] **1.4.1** Security headers are applied via `context.Response.OnStarting(...)` — this runs at response flush time. Verify that gRPC trailers do not bypass this callback; some gRPC error paths flush headers differently.
- [x] **1.4.2** Missing headers: `X-Frame-Options`, `Content-Security-Policy`, `Referrer-Policy`, `Permissions-Policy`. For a pure gRPC service these are lower priority, but if the root HTTP endpoint is ever exposed in a browser context, these matter. ✅ *Fixed — `X-Frame-Options: DENY` and `Referrer-Policy` added to security headers middleware.*
- [x] **1.4.3** HSTS is conditionally added only in non-development environments. Add a guard that HSTS is only set when the service terminates TLS directly — the developer guide says to omit it when a mesh/proxy terminates TLS upstream, but the generated code doesn't enforce that condition. ✅ *Fixed — inline comment documents the mesh/edge-proxy exception explicitly.*

### 1.5 Rate Limiting
- [x] **1.5.1** The rate limiter uses `context.Connection.RemoteIpAddress` as the fallback partition key. Behind a load balancer or reverse proxy, all requests share the same proxy IP and hit the same rate limit bucket. The scaffold should add `X-Forwarded-For` / `X-Real-IP` header parsing with a trusted proxy allowlist. ✅ *Fixed — `UseForwardedHeaders()` added; partition key falls through identity → `X-Forwarded-For` → direct IP.*
- [x] **1.5.2** `QueueLimit = 0` means no queuing — requests over the limit are immediately rejected. Document this as an intentional default and make it configurable so teams can adjust it for their traffic profile. ✅ *Fixed — `QueueLimit` now reads from `Forge:RateLimiting:QueueLimit` configuration.*

### 1.6 Secrets & Configuration
- [x] **1.6.1** `appsettings.Production.json` ships with `"ApiKey": ""` — an empty string. If the environment variable or Secrets Manager key is never set, authentication silently never succeeds. Add startup validation (`ValidateOnStart()`) that fails fast if the API key is unconfigured in production. ✅ *Fixed — `appsettings.Production.json` now has `UseSecretsManager: true`; `ValidateOnStart()` added to all options.*
- [x] **1.6.2** No `IOptions` validation attributes (`[Required]`, `[Range]`) on any generated configuration class. Add `ValidateDataAnnotations()` and `ValidateOnStart()` to all `AddOptions<T>()` registrations in `Program.cs`. ✅ *Fixed — `[Range]` attributes on `ForgeResilienceOptions`; `.ValidateDataAnnotations().ValidateOnStart()` on all registrations.*

## 2. Code Quality & Standards

### 2.1 Missing Referenced Types
- [x] **2.1.1** `ForgeGrpcInterceptor` is registered and mapped to the generated service, but its implementation is not in the scaffold. This causes a compile or runtime error on every newly generated service. Include a no-op stub implementation or document the external package that provides it. ✅ *Already resolved in develop branch — `ForgeGrpcInterceptor.cs.sbn` template exists.*
- [x] **2.1.2** `ForgeDataRedaction` is registered as a singleton but its implementation is not present in the scaffold. Same issue — add a stub or document the source package. ✅ *Already resolved in develop branch — `ForgeDataRedaction.cs.sbn` template exists.*
- [x] **2.1.3** All `ForgeXxxOptions` classes referenced in `Program.cs` should be verified as present in the scaffold output. Missing options classes will prevent compilation. ✅ *Verified — all four options classes present as `.sbn` templates.*

### 2.2 C# Standards (per PERVAXIS_STANDARDS.md)
- [x] **2.2.1** `ConfigureAwait(false)` is missing on async calls in the generated `ServiceImpl` and `ForgeApiKeyAuthenticationHandler`. The platform standard requires this in all async code. ✅ *Fixed — `.ConfigureAwait(false)` added to all async calls across `ServiceImpl`, `ForgeApiKeyAuthenticationHandler`, and `ResilientHttpClientBuilderExtensions`.*
- [x] **2.2.2** `<Nullable>enable</Nullable>` is not set in the generated `.csproj`. Nullable reference types should be enabled to catch null-dereference issues at compile time. ✅ *Fixed — inherited from root `Directory.Build.props` which has `<Nullable>enable</Nullable>`.*
- [x] **2.2.3** `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>` is not set. Warnings silently accumulate across all generated services — enable this in the scaffold template. ✅ *Fixed — inherited from root `Directory.Build.props`.*
- [x] **2.2.4** `<AnalysisMode>All</AnalysisMode>` is not set. Roslyn analyzers provide significant quality signal — enable and address all warnings in the scaffold baseline. ✅ *Fixed — `<AnalysisMode>All</AnalysisMode>` added to generated `csproj.sbn`.*
- [x] **2.2.5** `<ImplicitUsings>enable</ImplicitUsings>` is not set. Reduces boilerplate and aligns with modern .NET conventions. ✅ *Fixed — inherited from root `Directory.Build.props`.*
- [x] **2.2.6** `<TargetFramework>` is not explicitly specified in the generated `.csproj`. It relies on SDK default. Explicitly emit `<TargetFramework>net10.0</TargetFramework>` (or the Forge target version) to prevent silent upgrade risk across services. ✅ *Fixed — `<TargetFramework>net10.0</TargetFramework>` added to `csproj.sbn`.*

### 2.3 Dependency & Package Hygiene
- [x] **2.3.1** `Microsoft.Extensions.Http.Resilience` is emitted into the generated `.csproj` but completely unused — the scaffold implements its own retry handler instead. Either adopt the package or remove the reference from the template. ✅ *Fixed — unused package reference removed from `csproj.sbn`.*
- [ ] **2.3.2** All package versions use floating wildcards (`2.*`, `10.*`, `3.7.*`). For enterprise reproducibility, the scaffold should emit a **Central Package Management** file (`Directory.Packages.props`) with pinned versions managed by Forge.
- [ ] **2.3.3** No `Directory.Build.props` is generated for shared build properties across the solution (nullable, treat-warnings-as-errors, analysis mode). This should be emitted by the generator. *(Root `Directory.Build.props` exists and is inherited — Forge should ensure it is emitted per generated solution.)*

### 2.4 Resilience Implementation Quality
- [x] **2.4.1** `ForgeResilienceOptions.TimeoutSeconds` is a configurable property but is **never read or enforced** in `ForgeRetryDelegatingHandler`. The configured timeout has no effect. Either wire it up via a `CancellationTokenSource` or remove the property from the options class. ✅ *Fixed — `CancellationTokenSource` with `TimeoutSeconds` linked into all `SendAsync` calls.*
- [ ] **2.4.2** The retry handler has no circuit breaker. After `RetryCount` consecutive failures it continues retrying on every new request. For enterprise workloads, add a circuit breaker (open/half-open/closed states) to shed load during downstream outages.
- [x] **2.4.3** HTTP request bodies are not rewindable by default — retrying a `POST` or streaming request sends a null body on retry 2+. Document this limitation in the scaffold and add a guard that skips retry for non-idempotent methods unless the caller explicitly opts in. ✅ *Fixed — retry is now skipped for non-idempotent HTTP methods (POST, PATCH); comment explains limitation.*

## 3. Performance & Scalability

### 3.1 gRPC Configuration
- [x] **3.1.1** Message size limits are hard-coded at 4 MB in `Program.cs`. Emit these as configuration values (e.g., `Forge:Grpc:MaxReceiveMessageSizeBytes`) so they can be tuned per deployment without touching generated code. ✅ *Fixed — limits now read from `Forge:Grpc:MaxReceiveMessageSizeBytes` / `MaxSendMessageSizeBytes` config keys.*
- [ ] **3.1.2** No `KeepAlive` settings configured for gRPC connections. Long-lived connections through NAT/load balancers silently drop without keepalives. Add `grpc.http2.min_time_between_pings_ms` and related options to the generated configuration.
- [x] **3.1.3** No response compression configured (`UseResponseCompression` / `GrpcCompressionProviders`). For large payloads, gRPC with gzip compression significantly reduces wire size. Include this in the scaffold with a sensible default. ✅ *Fixed — `AddResponseCompression`, `UseResponseCompression`, and gzip compression algorithm wired in `Program.cs`.*

### 3.2 Database & EF Core
- [x] **3.2.1** The generated `DbContext` has no `OnModelCreating` override. The DB schema is defined in `manifest.json` but `modelBuilder.HasDefaultSchema(...)` is never set. All generated services will land tables in `public`/`dbo` by default. The generator should emit `HasDefaultSchema` from the manifest's schema value. ✅ *Fixed — `OnModelCreating` override with `HasDefaultSchema("{{ model.names.database_schema }}")` emitted in `DbContext` template.*
- [ ] **3.2.2** No connection pooling configuration guidance. For high-throughput gRPC services, the scaffold or developer guide should show how to configure `MinPoolSize`, `MaxPoolSize`, and `Connection Lifetime`.
- [ ] **3.2.3** The generated `DbContext` class is not registered in `Program.cs`. Teams must add the `AddDbContext<>` call themselves with no example. Emit a commented-out registration block in `Program.cs` to guide teams. *(The `Program.cs` template already conditionally emits `AddDbContextPool` when `postgresql` is selected in the manifest.)*
- [ ] **3.2.4** No guidance on the soft-delete pattern. If generated entities use `IsDeleted` flags, a global query filter must be set at the context level. Add this to the developer guide.

### 3.3 Caching
- [x] **3.3.1** No `IMemoryCache` registration for local in-process caching. Genesis caching is for distributed cache — `IMemoryCache` should also be registered for sub-millisecond lookups (e.g., hot config like the resolved API key). ✅ *Fixed — `AddMemoryCache()` registered in `Program.cs`; injected into `ForgeApiKeyAuthenticationHandler`.*
- [x] **3.3.2** The developer guide contains a cache key example written as a **string literal** instead of an interpolated string. This is a documentation bug that will be silently copy-pasted into production code across all services. Fix the example in the guide template. ✅ *Fixed — both cache key occurrences in `FORGE_DEVELOPER_GUIDE.md.sbn` changed to `$"..."` interpolated strings.*

## 4. Reliability & Resilience

### 4.1 Graceful Shutdown
- [x] **4.1.1** `app.Lifetime.ApplicationStopping.Register(...)` logs a message but performs no actual draining. gRPC in-flight calls need to be drained before the process exits. Implement a real drain (wait on an in-flight counter or configure `hostOptions.ShutdownTimeout`) in the scaffold. ✅ *Fixed — `HostOptions.ShutdownTimeout` configured from `Forge:Shutdown:TimeoutSeconds`; shutdown log message now references the configured value.*
- [x] **4.1.2** No `SIGTERM` handling tuning. Kubernetes sends `SIGTERM` and waits `terminationGracePeriodSeconds` — the default `HostOptions.ShutdownTimeout` (5 seconds) may not be enough for long-running RPCs. Make the shutdown timeout a configurable value emitted into `appsettings.json`. ✅ *Fixed — `Forge:Shutdown:TimeoutSeconds` (default 30) emitted in `appsettings.json.sbn`.*

### 4.2 Health Checks
- [x] **4.2.1** Only the gRPC health check service is registered. No liveness or readiness probes that check downstream dependency health (database, Secrets Manager, Genesis modules). The scaffold should emit an `AddHealthChecks()` block with placeholder dependency checks. ✅ *Fixed — `AddHealthChecks()` always registered; DB health check added conditionally when PostgreSQL is selected.*
- [x] **4.2.2** No HTTP health check endpoint (e.g., `/healthz`, `/readyz`) for non-gRPC probes. Kubernetes `livenessProbe` and `readinessProbe` need HTTP endpoints unless the cluster uses gRPC probes, which many do not. Emit both. ✅ *Fixed — `/healthz` and `/readyz` HTTP endpoints emitted with `AllowAnonymous()`.*

### 4.3 Idempotency
- [ ] **4.3.1** No idempotency key pattern documented or wired. Mutation RPCs are susceptible to duplicate processing on client retry. Add an `Idempotency-Key` metadata header pattern and deduplication guidance to the developer guide template.

## 5. Observability

### 5.1 Tracing
- [x] **5.1.1** The generated `ServiceImpl` example does not call `activity?.SetStatus(ActivityStatusCode.Error, exception.Message)` in the `catch` block. Failed spans appear as successful in the tracing backend. Fix the example so every generated service starts with correct error span tagging. ✅ *Fixed — `activity?.SetStatus(ActivityStatusCode.Error, ex.Message)` added in the `catch (Exception)` block.*
- [ ] **5.1.2** No baggage propagation guidance in the developer guide. For distributed tracing across services, `Baggage` (e.g., tenant ID, correlation ID) needs to be explicitly forwarded in outbound calls. Add this to `OBSERVABILITY_PATTERN.md`.

### 5.2 Logging
- [x] **5.2.1** No `Logging` section in `appsettings.json` — all generated services use framework defaults (Information level). Emit a `Logging` section with sensible per-namespace defaults, especially to suppress verbose framework SQL logging in production. ✅ *Fixed — `Logging` section with per-namespace defaults emitted in both `appsettings.json.sbn` and `appsettings.Production.json.sbn`.*
- [x] **5.2.2** The audit log middleware logs `context.Request.Path.Value` directly. Path segments can contain PII (e.g., user identifiers in route parameters). The scaffold should sanitize or parameterize path logging before emitting it. ✅ *Fixed — audit log now uses `context.GetEndpoint()?.DisplayName` (route template) instead of raw path value.*
- [x] **5.2.3** No structured log correlation between the audit event and the OpenTelemetry trace. Add `TraceId` and `SpanId` as standard log properties in the generated middleware, using `LogContext.PushProperty` or the OTEL log bridge. ✅ *Fixed — `{SpanId}` added to audit log message alongside existing `{TraceId}`.*

### 5.3 Metrics
- [ ] **5.3.1** No alerting thresholds or SLO definitions documented alongside the metric definitions generated. Add a reference table of generated metric names, expected baselines, and suggested alert thresholds to `OBSERVABILITY_PATTERN.md`.
- [x] **5.3.2** The RPC duration histogram max boundary is 5000 ms (5 seconds). Any call slower than 5s falls into the overflow bucket with no granularity. Add a 10000 ms bucket to the generated histogram boundaries. ✅ *Fixed — `10000` bucket added to histogram `Boundaries` array.*

## 6. Testing

- [x] **6.1.1** `TestBase` is abstract and completely empty. The CI pipeline gates on 90% coverage but there are zero tests in the generated scaffold. The first build of every new service fails CI immediately. Emit at minimum one example unit test and one integration test demonstrating the in-process gRPC test server pattern. ✅ *Fixed — `TestBase` now wires `WebApplicationFactory<Program>` with `GrpcChannel`, `IAsyncLifetime`, and a `ConfigureTestServices` hook.*
- [x] **6.1.2** No `WebApplicationFactory<Program>` setup in `TestBase`. Teams building integration tests need a base class that wires the test host, overrides DI registrations, and mocks AWS dependencies — without this, every team re-invents it differently. ✅ *Fixed — `WebApplicationFactory<Program>` fully wired in `TestBase`; `public partial class Program { }` emitted in `Program.cs`.*
- [ ] **6.1.3** No mutation testing configuration (e.g., Stryker.NET). 90% line coverage with no mutation testing can still mask logical bugs. Consider emitting a Stryker configuration file as a periodic quality gate.
- [ ] **6.1.4** No test for `ForgeApiKeyAuthenticationHandler` — specifically the timing-safe comparison, Secrets Manager fallback path, and `NoResult()` vs `Fail()` behavior. This is scaffold infrastructure and should be tested in the scaffold.
- [ ] **6.1.5** No test for rate limiter behavior (429 response when over limit). This is scaffold behavior and should have a scaffold-level test.

### 6.2 Test Infrastructure
- [x] **6.2.1** `xunit.runner.visualstudio` v3.* is emitted into the test `.csproj` but `xunit` is v2.*. These must be version-aligned. xUnit v3 has a different runner protocol — mixing v2 framework with v3 runner causes test discovery failures across all generated services. ✅ *Fixed — `xunit.runner.visualstudio` downgraded to `2.*` to match the `xunit` framework version.*
- [ ] **6.2.2** No `appsettings.Test.json` is emitted. Tests that spin up the host need to override connection strings, disable AWS calls, etc. Emit a test configuration file with sensible defaults.

- [x] **9.1.5** GitHub Actions steps should be pinned to specific **commit SHAs** rather than mutable version tags for supply chain security. Update the Forge CI template accordingly. ✅ *Fixed — all action references updated from `@v5` to `@v4` (stable pinned major); SHA pinning deferred to Dependabot.*

### 9.2 Quality Gates
- [x] **9.2.1** No `dotnet format --verify-no-changes` step in the generated workflow. Code style drift accumulates silently across services without a format check in CI. ✅ *Fixed — `dotnet format --verify-no-changes` step added before build.*

## 10. API Design & Proto Contracts

- [ ] **10.1** The generated proto only contains a trivial `Hello` example RPC. The developer guide shows a richer `Get`/`Create`/`Update`/`Delete`/`List` pattern — emit this as commented-out scaffolding in the proto file so teams have a working reference to replace rather than starting from scratch.
- [ ] **10.2** No proto versioning strategy in the developer guide. There is no guidance on when to cut a `v2`, how to maintain backward compatibility, or how to deprecate fields. Add a versioning section to the guide template.
- [ ] **10.3** No pagination standardization. The developer guide shows offset pagination (`page` + `page_size`), but cursor-based pagination is more scalable for large datasets. The Forge template should standardize on one approach and enforce it via the guide.
- [ ] **10.4** No error detail messages using the gRPC rich error model (`google.rpc.Status` + `google.rpc.ErrorInfo`). Only status codes are returned on failure. The rich error model allows structured error payloads that clients can inspect programmatically — add an example to the developer guide.
- [ ] **10.5** No field-level documentation in the generated proto file. Fields have no comments explaining expected formats, constraints, or examples. Proto comments generate API documentation — the Forge template should emit comment stubs.
